Mentions bills by usage: what you track, and what the pipeline actually finds for you. There are no seats, no tiers, and one subscription per organization.

## Pricing model

| Line | Price | How it accrues |
| --- | --- | --- |
| Keywords | 5 EUR per keyword per month | Prorated per day. A keyword tracked for 12 days costs 12/30 of the monthly price |
| Mentions | 8 EUR per 1,000 past your allowance | The first 100 mentions each cycle are free, org-wide. Keywords bundle no mentions |

A mention counts when the pipeline finds a post matching one of your keywords, whether the classifier scores it relevant or filters it as noise. Both numbers are shown in the dashboard and returned by the usage endpoint, so the billing counter never disagrees with what you can see.

Billing cycles are calendar months (UTC). Two rules always work in your favor:

- **Partial units are forgiven.** Overage is billed in whole 1,000-mention units; a leftover 999 mentions cost nothing, and the pool never bills fractionally.
- **Failed classifications are never billed.** If the classifier errors out on a mention, it is not counted. An outage on our side costs you nothing.

## Plan limits

| Plan | Keyword limit |
| --- | --- |
| Free (no subscription) | 2 keywords |
| Active subscription | 500 keywords |

Creating or unmuting a keyword past your limit fails with `402 keyword_limit_reached`. The check is atomic with the write, so concurrent requests cannot race past the limit.

## Subscribe

Create a hosted checkout session and send the user to the returned URL:

```bash
curl -X POST "$MENTIONS_API_URL/v1/billing/checkout" \
  -H "Authorization: Bearer $MENTIONS_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{ "successUrl": "https://app.example.com/settings?checkout=success" }'
```

```json
{ "url": "https://polar.sh/checkout/..." }
```

`successUrl` must be `https` and its origin must be one the deployment trusts (the same allowlist as dashboard auth).

## Manage the subscription

The customer portal handles payment methods, invoices, and cancellation:

```bash
curl -X POST "$MENTIONS_API_URL/v1/billing/portal" \
  -H "Authorization: Bearer $MENTIONS_API_KEY"
```

```json
{ "url": "https://polar.sh/portal/..." }
```

Returns `404 not_found` until the organization's first checkout has completed, because no billing account exists yet.

## Check usage

```bash
curl -H "Authorization: Bearer $MENTIONS_API_KEY" \
  "$MENTIONS_API_URL/v1/billing/usage"
```

```json
{
  "cycle": "2026-08",
  "status": "active",
  "activeKeywords": 5,
  "keywordMax": 6,
  "matchedMentions": 12840,
  "includedMentions": 100,
  "overageMentions": 12740,
  "billableMentions": 12740,
  "billedMentions": 12000,
  "trial": null
}
```

| Field | Meaning |
| --- | --- |
| `cycle` | Current calendar-month cycle (UTC) |
| `status` | `none`, `active`, `past_due`, or `canceled` |
| `activeKeywords` | Unmuted keywords right now |
| `keywordMax` | The cycle's keyword high-water mark; the keyword bill line derives from it |
| `matchedMentions` | Every mention matched to a keyword this cycle, relevant or not. This is the billed count |
| `includedMentions` | Flat free allowance per cycle (100, org-wide). Keywords bundle no mentions |
| `overageMentions` | Mentions past the free allowance |
| `billableMentions` | Overage accrued so far; billed in whole 1,000s |
| `billedMentions` | Mentions already reported to the billing provider |
| `trial` | Trial state for orgs without a subscription, else `null` |

<Callout title="Billing errors favor you">
  Usage is metered so that an error can only ever under-count, never over-bill. If a
  deployment has no billing credentials configured, billing endpoints return
  `503 billing_not_configured` and everything else keeps working on the free plan.
</Callout>
